Canvas

A grid you arrange once

Drag, drop and resize on a real grid. Widgets snap, the layout persists itself, and every canvas stays yours to rearrange whenever the question changes.

  • Multiple saved dashboards per account
  • Per-widget minimum sizes, so nothing renders unreadable
  • Star the canvas you open every morning
  • Light and dark, with the full Bussola palette
Connections

Tested before it is saved

Add a source, paste its token, and Bussola makes a real request against the provider before writing anything. A wrong key fails in the form — not silently, three days later, inside a widget.

  • Secrets encrypted with AES-256-GCM at rest
  • Credentials scoped per user, never shared across tenants
  • Re-test any connection from the connections page
  • Qonto accepts login:secret in one field
Sync

Widgets that never wait on an API

A background worker refreshes each connection on its own schedule and writes a snapshot. Every widget read is then a single local query — so a dashboard opens at the same speed whether one person or ten are watching.

  • Upstream traffic scales with connections, not viewers
  • Failing connections back off exponentially, at most hourly
  • Ten consecutive failures pause the sync and ask you to reconnect
  • Workers lease their work, so several can run without double-fetching
Onboarding

No empty states, ever

Until a source is connected, widgets render clearly-labelled sample data rather than blank boxes. You build the canvas you want first, then decide which tokens to paste.

  • Realistic figures across every widget type
  • Labelled as sample data — never mistaken for live numbers
  • Swaps to your real data the moment a connection syncs
Accounts

More than one of anything

A connection is not a provider slot. Two Stripe accounts, three Railway workspaces, a client’s Qonto beside your own — each widget picks which one it reads, and can narrow to a single project or service.

  • Unlimited connections per source, on every plan
  • Per-widget source, so one canvas can hold two businesses
  • Filter a block to one project, service, site or account
  • Trim a chart to the last 7, 14, 30 or 90 days
  • Every option reads the snapshot you already have — no extra API call
Sharing

Send a link, not a screenshot

Give a client or a co-founder a read-only view of one canvas. Get an email when something actually needs you — a failed deploy, a balance under your threshold.

  • Read-only dashboard links, revocable, with an optional expiry
  • Only a hash of the link is stored — a leaked backup hands out nothing
  • White-label sharing on Team, for client reporting
  • Email alerts from Solo up; Slack and Discord webhooks on Team
  • Alerts fire on the change, not once per sync — and a recovery is never held back
Agents

An MCP server with a short leash

Point an assistant at Bussola and it can read every connector and rearrange your dashboards. What it cannot do is written into the server, not into a prompt.

  • Read data across all connectors
  • Create dashboards, add, move and remove widgets
  • Never edits credentials — the web UI is the only place
  • Never writes to a third-party system
  • Read-only tokens are refused every write, at the server
  • Plan limits apply to an agent exactly as they do to you
